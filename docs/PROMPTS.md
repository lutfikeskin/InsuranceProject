# Prompting and Extraction Guidance

This guide documents prompt behavior currently used by the extraction pipeline.

## Implemented Prompt Surfaces

- Prompt definitions are in `modules/extraction/prompts.py`.
- Extraction pipeline wiring is in `modules/extraction/pipeline.py`.
- Structured response schemas are in `modules/extraction/schemas.py`.

## Current Pipeline Reality

- Current flow uses a classification call followed by one routed extraction call in `GeminiExtractionPipeline.run()`.
- The request uses:
  - `response_mime_type="application/json"`
  - a routed response schema (`COMPLETE_POLICY_SCHEMA`, `COI_SUMMARY_SCHEMA`, or `ENDORSEMENT_SCHEMA`)
  - `thinking_budget=0`
- A dynamically generated registry JSON is injected through `get_extract_all_prompt(...)` for full policy extraction.
- Manual `policy_type` selection fixes policy type but still allows document-type routing.

## Prompt Design Principles

1. Prefer explicit extraction instructions over generic language.
2. Map coverage names to canonical ontology codes.
3. Keep instructions concise to control token usage.
4. Return structured fields; avoid free-form narrative outputs.
5. Preserve nulls for truly missing fields rather than fabricating values.

## Registry Injection

- Registry payload is generated by `get_cached_registry_json(policy_type)`.
- Entries are minified (`f`, `s`, `l`) to reduce token usage.
- Policy-type constraints are applied when `policy_type` is known.

## Routed Prompt Surfaces

- Full policy documents use `get_extract_all_prompt(...)`.
- COIs and memorandums use `get_extract_coi_prompt(...)`.
- Endorsements use `get_extract_endorsement_prompt(...)`.
- Quotes and applications are classified but not extracted as active coverage.

Full-policy prompts include policy-type scoped instruction blocks when policy type is known:

- Auto policies keep vehicle, driver, physical damage, UM/UIM/PIP, and covered auto symbol guidance.
- GL/BOP/package policies emphasize liability limits and reduce vehicle/driver instructions unless schedules are present.
- Motor truck cargo policies emphasize cargo, DOT/MC/MCS-90, and scheduled vehicle details.
- Umbrella/excess policies emphasize underlying policy references and umbrella limits.

## Carrier and State Context

- Carrier hints are loaded from extraction knowledge base helpers.
- State hint behavior is documented in [`STATE_RULES.md`](STATE_RULES.md).

## Validation Interaction

Prompt outputs are post-processed by pipeline logic:
- zero-value cleanup for numeric coverage fields
- ontology validation for coverage code/family/structure consistency
- policy-type filtering
- CSL-vs-split cleanup for auto liability in auto policy types

See [`EXTRACTION_PIPELINE.md`](EXTRACTION_PIPELINE.md) for full lifecycle.

## Carrier vs Underwriter Rule

Prompt guidance now enforces a strict split:

- `carrier_name`: customer-facing brand (for example Progressive, GEICO, Allstate)
- `underwriter_name`: legal underwriting entity when present in fine print/declarations

Extraction behavior:

- If only one insurer name appears, populate `carrier_name` and keep `underwriter_name` null.
- If both appear, populate both.
- Never invent `underwriter_name` when uncertain.

For COI/memorandum extraction, the producer must come from a dedicated PRODUCER box/section. Carrier or insurer names must not be used as a fallback producer.

## COI Address and Med Pay Rules

The COI/memorandum prompt asks for structured insured address components when visible:

- `insured.address` should hold the street address.
- `insured.city`, `insured.state_code`, and `insured.zip` should be filled only from visible text.
- One-line US addresses may be split when the city/state/ZIP pattern is clear.

COI policy row limits treat `Medical Payments`, `Med Pay`, `MEDICAL PAYMENTS INCL`, and `Included` as Medical Payments evidence. If no numeric value is shown, the prompt returns `limits.med_pay_limit = "Included"`.

## Null Handling

Prompts require JSON null for missing values and explicitly reject placeholder strings such as `"null"`, `"N/A"`, `"-"`, and `""`. COI normalization also cleans these placeholders from policy rows before persistence.
